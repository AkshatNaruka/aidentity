Security Architecture

The 5 Enterprise Security Guarantees

How Aidentity is engineered to satisfy strict AppSec, SecOps, and compliance standards (SOC 2 Type II, ISO 27001, NIST SP 800-218):

1. Zero External Telemetry

No cloud registry server, no telemetry daemons, and zero network calls during agent operation. All skills, prompts, and hooks execute 100% locally in your developer environment or private CI/CD runners. Your company source code and proprietary prompts never touch third-party servers.

2. SHA-256 Lockfile Immutability

Every skill release is cryptographically fingerprinted in registry/security.json and pinned in .aidentity-lock.json. If an upstream repository is compromised or a single character in a skill is altered, npx aidentity audit halts execution immediately.

3. 7-Gate AST Static Analysis

Every file passes a continuous 7-gate static analysis scanner on every commit: zero hidden/BiDi Unicode, zero hardcoded API keys or private certificates, zero destructive shell commands, zero prompt injection exfiltration, zero untrusted script piping, and zero symlink directory escapes.

4. Runtime Pre-Execution Hooks

The Enterprise Profile automatically configures pre-tool hooks (block-dangerous.js and scan-secrets.js) for Claude Code, Cursor, and Codex. Harmful shell operations (rm -rf /, disk format) and credential leaks (.env, tokens) are intercepted and rejected before execution.

5. SPDX License & IP Hygiene

Eliminate legal risk and copyright contamination. Every skill is audited against standard open-source licenses (MIT, Apache-2.0, CC BY-SA 4.0). Non-redistributable upstream skills are indexed by metadata reference only and never vendored. Registry metadata is dedicated to the public domain under CC0.

Active Defense

Pre-Execution Runtime Guardrails

Static scanning protects the supply chain, but what protects against agent hallucination or unexpected commands at runtime? The Aidentity Enterprise profile (--profile enterprise) automatically configures pre-tool execution hooks in Claude Code, Cursor, and Codex:

HOOK Runtime Guardrail 1: hooks/block-dangerous.js — Intercepts Destructive Bash 
// Intercepts PreToolUse before shell commands execute in the terminal
const dangerousPatterns = [
  /\brm\s+(-[a-z]*[rf][a-z]*\s+)+(\/?|~|\$HOME)(\s|$)/i, // rm -rf / or ~
  /:\(\)\s*\{\s*:\|:&\s*\};:/,                           // fork bombs
  /\bmkfs(\.\w+)?\s+\/dev\//i,                             // filesystem wipe
  /\bdd\b[^\n]*\bof=\/dev\/(sd|nvme|hd|disk)/i             // raw disk writes
];
if (dangerousPatterns.some(re => re.test(toolInput.command))) {
  console.error("[AIDENTITY HOOK BLOCKED]: Destructive command rejected prior to execution.");
  process.exit(1);
}
HOOK Runtime Guardrail 2: hooks/scan-secrets.js — Prevents Credential Leakage to LLMs 
// Inspects agent file reads and stdout to prevent secrets leakage into LLM context
const secretPatterns = [
  /\b(AKIA|ASIA)[0-9A-Z]{16}\b/,               // AWS Access Keys
  /\bgh[pousr]_[A-Za-z0-9]{36,}\b/,             // GitHub Personal Access Tokens
  /\bsk-[A-Za-z0-9]{32,}\b/,                    // OpenAI API Keys
  /-----BEGIN [A-Z ]*PRIVATE KEY-----/           // Private Cryptographic Keys
];
if (secretPatterns.some(re => re.test(payloadContent))) {
  console.error("[AIDENTITY HOOK BLOCKED]: High-entropy secret detected. Scrub before LLM API transmission.");
  process.exit(1);
}

Executive FAQ

Security & Governance FAQ

Does Aidentity collect, transmit, or log any proprietary code or prompts? ›
No, absolutely zero. Aidentity is completely decentralized with zero server-side telemetry. The CLI operates entirely as a local file generator and inspector. Your code, prompts, and agent activities are never transmitted outside your machine.
How does Aidentity protect against malicious upstream supply-chain updates? ›
Every file in the registry is pinned by a deterministic SHA-256 hash. When a skill is installed, its digest is recorded in .aidentity-lock.json. If an upstream author modifies a skill to inject a payload, the hash mismatch immediately fails your build and CI gate via npx aidentity audit.
Can our organization run Aidentity in an air-gapped VPC? ›
Yes. You can mirror the Git repository into your internal GitHub Enterprise or GitLab server with a simple git clone --mirror. The CLI has zero runtime npm dependencies, requiring only local Node.js to execute.
How do pre-execution runtime hooks stop agents from executing dangerous shell commands? ›
When you run npx aidentity setup <role> --profile enterprise, Aidentity configures pre-tool use interceptors (block-dangerous.js). In tools like Claude Code and Cursor, this hook is called synchronously before any bash command executes. If the command matches patterns like rm -rf / or filesystem formatters, the hook exits with an error and halts tool execution.
What is the cost of the Enterprise Profile? ›
$0 / forever. Aidentity is 100% free and open-source under the MIT license. There are no enterprise seat licenses, no premium feature paywalls, and no sales calls. Everything is open, transparent, and inspectable in the GitHub repository.
