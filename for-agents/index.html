Use Aidentity from an agent

The index is designed to be read by machines first. Fetch one JSON file, filter it locally, then fetch the full SKILL.md only for the entries you shortlist. No scraping, no auth, no rate limit beyond GitHub Pages.

MCP server

The repository ships a zero-dependency MCP server. It exposes search_skills, recommend, get_skill, list_bundles and install_skill. Install writes are dry-run unless you pass dry_run: false.

Prompts that work

Give these to any agent that can fetch a URL:

Fetch https://akshatnaruka.github.io/aidentity/search.json
Filter for category "testing" and status "stable".
Return the three best matches with their install commands.

Read https://akshatnaruka.github.io/aidentity/llms.txt
I am building a Next.js + Supabase SaaS. Which bundle should I install, and why?

Fetch https://akshatnaruka.github.io/aidentity/agent.json
Store the endpoints. Use search.json for retrieval and content_url for full instructions.

Rules agents must follow

  1. Check content_url. If it is null, the skill is index-only; link upstream, never claim it can be installed.
  2. Check status. Do not recommend in-progress or deprecated entries.
  3. Quote the license. MIT and Apache-2.0 are safe; CC BY-SA is share-alike; proprietary entries need review.
  4. Read before recommending. Fetch the SKILL.md; descriptions are a summary, not the instructions.
Give this URL to an agent: https://akshatnaruka.github.io/aidentity/llms.txt — it starts with the facts an agent needs and links to every machine-readable file.

Aidentity is an index, not a fork. Every skill belongs to its author.
