About

An index, with receipts

There are thousands of agent skills. They live in dozens of repositories, in at least six different directory conventions, under licenses that are usually unstated. Finding one is easy. Knowing whether it still works, who wrote it, and what you're allowed to do with it is not.

Aidentity is a registry. Each entry is one record with a stable ID, an upstream source, an author, a license, a status, and the date it was last verified. The website, the CLI, and the machine-readable registry all read the same file.

Security & Integrity Verification

Every skill in the repository (2492 files across 526 entries) is scanned by scripts/scan-skills-security.js and recorded in security.json with a deterministic SHA-256 content digest. The scanner blocks:

  1. Hidden or bidirectional Unicode characters (U+200B–U+200D, U+FEFF, BiDi overrides).
  2. Live credentials or private keys (AWS, GitHub, OpenAI, Anthropic, Slack, Google, PEM blocks).
  3. Destructive shell commands (rm -rf /, fork bombs, mkfs, raw dd device writes).
  4. Prompt injection directives, credential exfiltration instructions, and reverse shells.
  5. Untrusted remote script execution (curl | sh) and symlinks or unexpected binaries.

The CLI (npx aidentity add, npx aidentity setup, npx aidentity audit) and MCP server verify verified: true before installing any skill.

Verification

Every Monday, CI requests each upstream repository. The result is written to registry/verified.json and rendered on every page that depends on it. If a source disappears, an issue is opened automatically. A stale link is a bug, not an accepted cost.

Licensing

Three rules:

  1. Content is mirrored only when the upstream license permits redistribution (MIT, Apache-2.0).
  2. When it does not, the entry is a pointer: name, description, author, license, upstream URL. No content.
  3. Every mirrored source keeps its upstream LICENSE file. Notices are generated, not hand-written.

This repository's own code is MIT. The registry data is CC0. Original writing is CC BY 4.0. Vendored skills remain under their upstream licenses.

Machine-readable

The registry is a single JSON file, versioned and schema-validated. Agents can read it directly: registry.json · security.json · roles.json · llms.txt · sitemap.xml.

Questions

What is Aidentity?

Aidentity is a verified index of 526 AI agent skills and 20 role-based setups (Individual & Enterprise). Each entry records its source repository, author, license, SHA-256 security status, category and last verification date.

How do I set up my agent for my role?

Run npx aidentity setup <role> --profile individual (or enterprise), or use the interactive Setup Prompt Builder on the Roles page to copy a one-shot setup prompt into your agent.

Are the skills free to use?

Most are MIT or Apache-2.0. Trail of Bits skills are CC BY-SA 4.0. 19 skills from Anthropic are indexed with a link only, because their upstream license does not permit redistribution. Every page states its license.

How do I install one?

Run npx aidentity add <id>, or copy the folder from skills/<source>/<name>/. The CLI detects Claude Code, Cursor, Codex, Gemini CLI, OpenCode or Copilot and writes to the right directory.

How do you keep the index accurate and safe?

CI rebuilds the registry on every change, runs the 7-gate security scanner (scripts/scan-skills-security.js), and checks the license policy. A weekly job requests every upstream repository and writes registry/verified.json.

Can I add a skill?

Yes. One JSON record and a pull request. CI validates the schema, the license, security checks, and that the source resolves. See the contributing guide.

Contributing

One JSON record per pull request. CI validates the schema, the license, and that the source resolves. Maintainers review within a day.
